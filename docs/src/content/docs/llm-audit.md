An **on-demand, optional** second opinion on a single flagged window, produced
by a **local Ollama model**. The deterministic quality model decides; the LLM
only explains.

## What it is

The LLM audit is an optional, on-demand explanation of a single flagged
window, generated by a model running under a **local Ollama** server. It sits
**off the decision path**: the deterministic quality model and the
[runtime guards](/biosqa/docs/runtime-guards/) make the call, and the LLM does
nothing more than **explain** that call in plain language.

> The LLM's self-reported grade is **never** consumed as a probability. A
> calibrated model over the SQIs beats the LLM at grading, so the audit is a
> narrative aid, not a second grader.

## How it works

For the selected window, the app sends the model three things:

- the window's **numeric SQI summary**,
- the **runtime guard's findings**, and
- the quality model's own **verdict**: carrying a real usability estimate
  rather than a misleading "confidence" number.

The local model returns a **structured second opinion**, which the app
displays. To reduce single-sample noise, the audit uses **self-consistency**:
it samples **k times (1–5 passes)** and takes a **majority vote** across the
returned opinions.

## Prerequisites & config

The audit requires a **local Ollama server** to be running. All of the
following are configured in [Settings](/biosqa/docs/settings/):

| Setting | Purpose |
| --- | --- |
| Enable / disable | Turn the audit on or off |
| Host | Address of the local Ollama server |
| Model | Which Ollama model to query |
| Self-consistency passes | Number of samples (1–5) to majority-vote |

> A **larger model** (e.g. `qwen3:32b`) produces structured JSON far more
> reliably than 7–9B models. If you see malformed or inconsistent output,
> prefer a larger model before adjusting anything else.

## Robustness

Audits run on a **dedicated worker** with a **bounded per-call timeout**, so a
slow or hung local model cannot stall the rest of the app:

- If a sample **times out mid-loop**, the earlier samples are still used.
- If **Ollama is absent**, the audit degrades gracefully to an error and the
  quality model's own verdict stands.

## When to use

Reach for the audit on a **puzzling segment**: for example a suspected
false-clean on pre-filtered input, where a plain-language sanity check helps
you reason about what the guards and SQIs are seeing. For routine triage,
**skip it**: the deterministic verdict is the decision, and the audit adds
latency without changing it.

See [runtime guards](/biosqa/docs/runtime-guards/) for the deterministic checks
that actually make the call.
